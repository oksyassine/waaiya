# Real-time voice-isolation plugins/SDKs and browser-based music removal (state as of 6 Nov 2026)

Scope note: (A) real-time plugins/SDKs that isolate speech/singing from music or noise, for hosting system-wide (Equalizer APO / Audio Hijack / PipeWire filter-chain) or licensing into an app; (B) browser-extension / in-page Web Audio approaches that remove music from any tab. Research method: web search (budget exhausted mid-task) plus direct fetches of vendor pages, docs, store listings and GitHub repos. Where a vendor page could not be fetched (rate-limited/404) this is stated in Gaps rather than guessed.

## Key question A1 — Product-by-product catalogue: real-time?, latency, CPU/GPU, what it separates, quality, price/licensing, platforms

### Takeaway
Only one vendor (AudioShake) explicitly sells a real-time, on-device model whose stated purpose is removing background music while keeping dialogue; every other mainstream "dialogue isolation" plugin (iZotope Dialogue Isolate, Waves Clarity Vx, Acon Extract:Dialogue 2, Antinode/Supertone Clear, Accentize dxRevive, CEDAR) is documented as a noise/reverb/ambience remover and never claims music removal. Typical real-time ML dialogue plugins add ~2048 samples (~43 ms at 48 kHz) of latency and run on CPU; GPU is required only by NVIDIA Maxine.

### Inferences
- For a system-wide desktop host today, the realistic shortlist is: (1) AudioShake Local Inference SDK (explicit real-time music removal, 11 ms Dialogue RT claim, Win/mac/Linux/iOS/Android, but sales-gated licensing and encrypted models), (2) iZotope RX 12 Standard's real-time Dialogue Isolate / Music Rebalance plugins ($399, VST3/AU/AAX only — no VST2, which matters for hosts limited to VST2), (3) Waves Clarity Vx / Pro (2048-sample latency, VST3/AU/AAX, OBS support, subscription or perpetual), (4) Antinode Clear ($49, VST/VST3/AU/AAX), (5) Acon Extract:Dialogue 2 ($99), (6) DeepFilterNet LADSPA on PipeWire (free, MIT/Apache, Linux only). All of (2)–(6) are per-seat plugin licences, not redistributable SDKs; only AudioShake, Krisp and NVIDIA Maxine are SDKs you can ship inside a product.
- At 48 kHz, the 2048-sample latency shared by RX Dialogue Isolate and Clarity Vx equals ~42.7 ms; with a 512-sample host buffer that is ~53 ms end-to-end plus OS audio latency — acceptable for video playback if the host can delay video, but noticeable for lip-sync without compensation.
- "Dialogue isolation" products are trained on noise/reverb/ambience; whether a music bed is treated as "noise" is undocumented for every plugin except AudioShake, so a developer must A/B test them on dialogue-over-music material rather than rely on marketing.

## Key question A2 — Which products explicitly target removing MUSIC behind speech, and which keep singing?

### Takeaway
Explicit "remove music, keep speech" claims exist only from AudioShake (real-time SDK + `music_removal` API), iZotope RX 12 Scene Rebalance (dialogue/music/effects, Advanced tier, real-time status unknown), Moises Live (consumer, real-time, system-wide), and offline cloud tools (LALAL.AI Voice Cleaner, ElevenLabs Voice Isolator with a caveat). Tools that keep singing voice are the stem separators (RX Music Rebalance, Moises, Demucs/UVR-based tools, AudioShake vocals stems), not the dialogue isolators.

### Inferences
- A "mute instruments, keep all human voice including nasheed/singing" product needs a vocals-vs-accompaniment stem model (Demucs/UVR-MDX-NET/AudioShake vocals), whereas "keep only speech" needs a dialogue-vs-music model (AudioShake Dialogue RT / music_removal, RX Scene Rebalance). Dialogue-isolation denoisers (Clarity Vx, Clear, Extract:Dialogue, DeepFilterNet, RNNoise, Krisp) are the wrong model class for music beds unless testing shows otherwise.
- AudioShake's own pricing signals difficulty: music_removal costs ~6.7x the plain dialogue stem (10 vs 1.5 credits/min).

### Gaps
- No vendor demo videos or forum A/B comparisons of dialogue-isolators on music beds were found before the search budget ran out; YouTube comparison evidence is absent from these notes.
- Whether RX 12 Dialogue Isolate's upgraded network handles music beds is undocumented.

## Key question A3 — Open-source engines, licences and plugin scaffolds (for shipping inside a product)

### Takeaway
DeepFilterNet (MIT/Apache-2.0, code and weights) and RNNoise (BSD-3) are the only mature permissively-licensed real-time speech enhancers; facebook/denoiser is CC-BY-NC-4.0 (non-commercial) and archived; anira (Apache-2.0) is the ready-made real-time inference scaffold for JUCE VST3/CLAP plugins; in-browser Demucs (free-music-demixer) is MIT for code but proprietary weights and far from real time.

### Cited Findings
- DeepFilterNet: "All code and model weights in this repository" dual-licensed MIT or Apache-2.0; ships a LADSPA plugin with PipeWire filter-chain integration; DeepFilterNet2 is default, DeepFilterNet3 ("Perceptually Motivated Real-Time Speech Enhancement") and a multi-frame hearing-aid variant exist; framework supports Linux/macOS/Windows (demo Linux-only); `deep-filter` accepts 48 kHz WAV only; ~1,603 commits, ~5k stars; no VST/CLAP build mentioned — [DeepFilterNet GitHub](https://github.com/Rikorose/DeepFilterNet)
- LADSPA plugin uses "a new model without any lookahead"; minimum latency 20 ms (STFT) plus host latency; provides `deepfilter-mono-source.conf` (virtual mic) and `deepfilter-stereo-sink.conf` (virtual output that "filters noise from application audio, leaving mostly speech") — [LADSPA README](https://github.com/Rikorose/DeepFilterNet/blob/main/ladspa/README.md)
- Original DeepFilterNet real-time factor 0.19 on a single-threaded notebook CPU — [arXiv 2305.08227](https://arxiv.org/abs/2305.08227)
- RNNoise: BSD-3-Clause; input 48 kHz 16-bit mono PCM; build with AVX2/SSE4.1 recommended; noise dataset updated 2025-01-30; music not mentioned — [xiph/rnnoise](https://github.com/xiph/rnnoise); processes 480-sample (10 ms) frames — [Jitsi blog](https://jitsi.org/blog/enhanced-noise-suppression-in-jitsi-meet/)
- facebook/denoiser: licence CC-BY-NC 4.0; repository archived read-only 2023-10-31; live mode `python -m denoiser.live` needs a loopback device (Soundflower / PulseAudio null sink); RTF 0.8 (1 thread) / 0.6 (4 threads) for H=48 on a 2 GHz quad-core i5; total lag 41.3 ms; `-f 2` adds ~16 ms per increment; trained on stationary/non-stationary noise and room reverb — [facebookresearch/denoiser](https://github.com/facebookresearch/denoiser)
- anira: Apache-2.0; backends LibTorch, ONNX Runtime, LiteRT, legacy TFLite, ExecuTorch; static thread pool moves inference off the audio callback; `get_latency()` in samples; platforms macOS (x86_64/arm64), Linux (x86_64/aarch64), Windows (x86_64/arm64), Android, iOS (static-only), WebAssembly via Emscripten (ONNX Runtime only); examples: JUCE VST3, CLAP, nn-inference-template; real-time safety checked with rtsan — [anira GitHub](https://github.com/anira-project/anira); paper by Ackva & Schulz, IEEE IS2 2024 — [arXiv 2506.12665](https://arxiv.org/pdf/2506.12665)
- free-music-demixer: demucs.cpp (Eigen3) compiled to WASM with Emscripten; Demucs v4 htdemucs float16 weights ~81 MB (htdemucs_6s 53 MB), no quantization; timings ~41 min single-threaded or ~9 min with 8 workers for one track, ~20/~5 min for another; WASM/JS MIT-licensed, model weights proprietary; no real-time mode — [sevagh/free-music-demixer](https://github.com/sevagh/free-music-demixer); adding `-msse4.2` to `-msimd128` cut demixing time ~25% — [release v0.5.0-alpha](https://github.com/sevagh/freemusicdemixer.com/releases/tag/v0.5.0-alpha)
- Browser-side sizes: `rnnoise.wasm` (@jitsi/rnnoise-wasm 0.2.1) ~110 KB; `ort-wasm-simd-threaded.wasm` (onnxruntime-web 1.30.0) ~14 MB before any model; GTCRN speech enhancer has 23.7k parameters / 39.6 M MACs per second; packages: @shiguredo/rnnoise-wasm Apache-2.0, @sapphi-red/web-noise-suppressor MIT — [Fora Soft](https://www.forasoft.com/learn/ai-for-video-engineering/articles-ai/real-time-noise-suppression-krisp-rnnoise-deepfilternet-integration)
- NoMusic extension's engine "FastEnhancer" (speech enhancement, Standard and Lite variants) is "compiled ahead of time into a standalone WebAssembly module (no ONNX Runtime)", followed by RNNoise; extension licence ISC — [NoMusic GitHub](https://github.com/mohamedsadiqaguenaou/NoMusic)

### Inferences
- For a redistributable desktop engine with zero licensing friction, DeepFilterNet (Rust, LADSPA/PipeWire today) wrapped via anira or a thin JUCE/CLAP shell is the lowest-risk path — but it is a speech denoiser, not a music remover, so a Demucs/UVR-class vocals model (weights licence must be checked per model) is needed for the actual music-vs-voice task.
- facebook/denoiser is unusable commercially (CC-BY-NC) and unmaintained.

### Gaps
- No GitHub search was possible for "CLAP/VST demucs real-time", "juce onnx vocal isolation" or "RTNeural separation" projects; whether any open-source real-time neural *separation* plugin exists remains unverified.
- Licence of UVR-MDX-NET weights (used by Wakapippi) and htdemucs weights for commercial redistribution were not checked.

## Key question B1 — Browser architecture: Chrome tabCapture (MV3), offscreen docs, AudioWorklet + ML runtimes, latency/CPU, DRM, and non-Chrome/mobile browsers

### Takeaway
On desktop Chromium the pattern is proven: service worker → `tabCapture.getMediaStreamId()` → offscreen document (reason USER_MEDIA) → `getUserMedia` with the stream ID → AudioWorklet (128-sample blocks) + worker-side WASM/WebGPU model → `AudioContext.destination`; capturing a tab silences its own playback until you re-route it, and capture needs a user gesture per tab. Firefox (desktop and Android) has never implemented `tabCapture` (bug open since 2017), Chrome on Android has no extensions, Kiwi is dead (Edge Canary absorbed its extension support), so an extension cannot "cover most of the user's listening" on phones.

### Cited Findings
- Chrome tabCapture: "When a MediaStream is obtained for a tab, audio in that tab will no longer be played to the user" (like `getDisplayMedia()` with `suppressLocalAudioPlayback: true`); to keep hearing it, create an `AudioContext`, `createMediaStreamSource(stream)` and connect to the destination; capture "can only be called after the user invokes an extension" (e.g. action-button click); from Chrome 116 a stream ID obtained in a service worker can be used in an offscreen document when `consumerTabId` is omitted; the ID "can only be used once and expires after a few seconds if it is not used"; the page says nothing about DRM/protected content — [Chrome tabCapture reference](https://developer.chrome.com/docs/extensions/reference/api/tabCapture)
- Chrome offscreen API: reasons include USER_MEDIA ("interacting with media streams from user media, such as getUserMedia()") and AUDIO_PLAYBACK; AUDIO_PLAYBACK closes the document after 30 seconds without audio playing, other reasons impose no lifetime limit; only one offscreen document per extension (one per profile in split incognito mode); API Chrome 109+, `runtime.getContexts()` Chrome 116+, `offscreen.hasDocument()` Chrome 150+ — [Chrome offscreen reference](https://developer.chrome.com/docs/extensions/reference/api/offscreen)
- Developer report (Feb 2025): capturing from a content script muted the tab; doing `getUserMedia` in an offscreen document (or popup) and routing the source to the destination keeps the tab audible; architecture = service worker coordinates, offscreen document handles audio, content script handles UI — [chromium-extensions group](https://groups.google.com/a/chromium.org/g/chromium-extensions/c/JI7AW48PxGs/m/QZ69ZIx1AgAJ)
- Existence proof of the full MV3 chain: NoMusic uses `tabCapture` permission, an offscreen document (`offscreen.html/js`) hosting the audio graph, an AudioWorklet (`rnnoise-worklet.js`, `ring-buffer-audio-processor.js`) bridging frames to a worker that runs the AOT-compiled FastEnhancer WASM, with RNNoise afterwards; worker is woken by the worklet rather than polling; dual-mono processed once — [NoMusic GitHub](https://github.com/mohamedsadiqaguenaou/NoMusic)
- AudioWorklet delivers 128-sample blocks (~2.67 ms at 48 kHz) while RNNoise needs 480-sample (10 ms) frames, so a circular buffer is required; ITU-T G.114 one-way budget 150 ms — [Fora Soft](https://www.forasoft.com/learn/ai-for-video-engineering/articles-ai/real-time-noise-suppression-krisp-rnnoise-deepfilternet-integration)
- Jitsi runs RNNoise WASM inside the AudioWorklet with the module inlined (`SINGLE_FILE=1`) and compiled synchronously (`WASM_ASYNC_COMPILATION=0`) because the worklet cannot await promises; they moved off ScriptProcessorNode because main-thread processing made delay noticeable once the track was modified — [Jitsi blog](https://jitsi.org/blog/enhanced-noise-suppression-in-jitsi-meet/)
- ONNX Runtime Web detects SIMD and multithreading at startup; MobileNet V2 ran 3.4x faster with two threads + SIMD than plain WASM; `ort.wasm.simd` defaults true — [Microsoft Open Source blog](https://opensource.microsoft.com/blog/2021/09/02/onnx-runtime-web-running-your-machine-learning-model-in-browser/)
- WebGPU separation in an extension is shipping: Wakapippi runs UVR-MDX-NET on-device via WebGPU in real time; requires Chrome 113+ with WebGPU; "performance may be poor on weak GPUs"; cannot process multiple videos/tabs at once; disabling noise reduction roughly halves load — [Wakapippi listing](https://chromewebstore.google.com/detail/wakapippi-vocal-remover-e/mfdkjbkokfdnegolbddbacaafcekijgf)
- Demucs-class models are not real-time in WASM: minutes-per-song single-threaded (see A3) — [sevagh/free-music-demixer](https://github.com/sevagh/free-music-demixer)
- Firefox: bug 1391223 "implement tabCapture" is status REOPENED, priority P5 enhancement; a Mozilla engineer said the platform side is "largely already available" but no API shipped — [Bugzilla 1391223](https://bugzilla.mozilla.org/show_bug.cgi?id=1391223); MDN's Chrome-incompatibilities page lists only `debugger` and `declarativeContent` as unsupported and does not cover tabCapture — [MDN](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Chrome_incompatibilities); the MDN browser-compat-data repo has no `webextensions/api/tabCapture.json` (HTTP 404) — [BCD](https://github.com/mdn/browser-compat-data/blob/main/webextensions/api/tabCapture.json)
- Firefox for Android: Mozilla recommends Manifest V2 for Android because of missing parity; background service workers not supported (use event pages, bug 1573659); `web-ext lint` flags `ANDROID_INCOMPATIBLE_API`; host-permission UI gaps (bugs 1820867, 1812125) — [Extension Workshop](https://extensionworkshop.com/documentation/develop/developing-extensions-for-firefox-for-android/)
- Firefox fallback techniques are page-level: the "Tab Audio Recorder" add-on captures a playing audio/video element, else fetches a detected stream URL, else taps the page's own AudioContext (ISC, open source) — [AMO listing](https://addons.mozilla.org/firefox/addon/tab-audio-rec/)
- `HTMLMediaElement.captureStream()` has "Limited availability" (not Baseline; "does not work in some of the most widely-used browsers"); spec: Media Capture from DOM Elements — [MDN captureStream](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/captureStream); `AudioContext.createMediaElementSource()` is Baseline (all major browsers since April 2021) and re-routes the element's audio into the graph while the element's own controls keep working — [MDN createMediaElementSource](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/createMediaElementSource)
- Kiwi Browser (Chromium + extensions on Android) ended maintenance January 2025 and was pulled from Play Store; its extension code was integrated into Microsoft Edge Canary for Android where extensions are installed by pasting an ID in developer options; Firefox and Samsung Internet also offer extensions on Android — [AlternativeTo](https://www.alternativeto.net/news/2025/1/kiwi-browser-discontinued-explore-alternatives-for-extension-support-and-security/); [Android Authority](https://androidauthority.com/kiwi-browser-shutting-down-3519510)
- Firefox for Android does list audio-processing extensions (HaramMute is published under the /android/ catalogue) — [AMO Android](https://addons.mozilla.org/en-US/android/addon/harammute/)
- DRM (indirect evidence only): Firefox lets Windows block DRM-protected video from capture "by design"; disabling hardware acceleration is a reported workaround — [Bugzilla 1866638](https://bugzilla.mozilla.org/show_bug.cgi?id=1866638); screen recorders typically get black video for protected streams "while the audio may be recorded successfully" (low-quality guide site) — [thelashlounge guide](https://old.thelashlounge.com/?p=33355)
- Karafilt claims to work on any tab including Spotify Web and SoundCloud (Chrome, Edge, Brave, Arc, Vivaldi, Opera), processing in WebAssembly — [Karafilt](https://karafilt.com/)
- Safari-side signal: LiveKit's Krisp WASM filter needs Safari ≥ 17.4 and Stream's audio-filters-web needs 17.4.1+, i.e. in-page WASM audio filters run in modern Safari — [Fora Soft](https://www.forasoft.com/learn/ai-for-video-engineering/articles-ai/real-time-noise-suppression-krisp-rnnoise-deepfilternet-integration)

### Inferences
- Per-tab user gesture + single offscreen document + "one tab at a time" (as Wakapippi documents) means a Chrome extension is practical for "the video I'm watching now", not a silent always-on filter across every tab.
- Latency budget inside the browser: 128-sample worklet quantum (2.7 ms) + model frame (10–20 ms for RNNoise/DeepFilterNet-class; hundreds of ms for STFT separation models) + worker hop; speech-enhancer-class models fit under 50 ms, stem-separation models (UVR-MDX-NET on WebGPU) are feasible only with a GPU and introduce visible A/V offset unless the extension also delays the video element.
- Because Karafilt reports working on Spotify Web (Widevine-protected audio), tabCapture most likely delivers audio from EME-protected tabs in Chrome; this is an inference from a vendor claim, not a documented guarantee.
- On Firefox (desktop/Android) the only path is a content script hooking the page's `<video>`/`<audio>` element with `createMediaElementSource` or `captureStream`; on YouTube (MSE blob source, same-origin) this works in practice for EQ extensions, but cross-origin media without CORS yields silence and EME content is not capturable — per Web Audio/mediacapture-fromelement specs (not fetched; flagged in Gaps).
- A browser extension therefore covers desktop Chromium users well, Firefox desktop partially (site-by-site hooks), Android only via Firefox/Edge Canary/Samsung Internet with site-specific hooks, and iOS not at all; it cannot be the "cover most listening" product on mobile.

### Gaps
- No primary Chrome documentation was found on tabCapture behaviour with EME/Widevine content (Netflix, Disney+, Spotify Web); the Spotify claim comes from one extension's marketing.
- Apple's "Assessing your Safari web extension's browser compatibility" page returned 404/empty on two URL variants; Safari's lack of `tabCapture`/`offscreen` is from general knowledge, not a fetched source.
- MDN's CORS/tainting note for `MediaElementAudioSourceNode` (silence for cross-origin media without CORS) was not captured in the fetched text; cite the Web Audio spec before relying on it.
- Whether Samsung Internet or Edge Canary on Android expose `tabCapture` is unknown.
- No measured CPU figures for running ONNX Runtime Web or WebGPU models inside an extension were found.

## Key question B2 — Existing extensions that do real-time per-tab audio effects (existence proofs and techniques)

### Takeaway
Several shipping Chrome extensions prove real-time per-tab ML or DSP audio processing: NoMusic (tabCapture + offscreen + worklet + WASM speech enhancer, open source), Wakapippi (UVR-MDX-NET on WebGPU), Karafilt (WASM spectral/center-channel vocal removal, MIT), plus several center-channel karaoke extensions; user counts are small (hundreds to ~1,000), suggesting the category is unproven commercially.

### Cited Findings
- NoMusic — "Watch Any Video Without Background Music": "Uses real-time artificial intelligence to automatically filter out and silence background music" in the active tab; "All audio processing happens directly inside your browser"; ~1,000 users, 4.8/5 from 34 ratings, v3.1.1 updated 2026-10-18, 1.19 MiB, open source — [Chrome Web Store](https://chromewebstore.google.com/detail/fepfnjijcojaoihcekfhonohejglmdbc); source shows tabCapture + offscreen + AudioWorklet + FastEnhancer WASM + RNNoise, ISC licence — [GitHub](https://github.com/mohamedsadiqaguenaou/NoMusic)
- Wakapippi Vocal Remover: UVR-MDX-NET run on-device with WebGPU, real-time vocals/accompaniment split; Chrome 113+; single tab only; 1,000 users, 4.4/5 (7 ratings), v1.0 updated 2026-07-24; audio not sent to servers — [Chrome Web Store](https://chromewebstore.google.com/detail/wakapippi-vocal-remover-e/mfdkjbkokfdnegolbddbacaafcekijgf)
- Karafilt: modes Spectral (keeps bass and stereo), Spectral Deep (also removes centre backing vocals), Basic (fast centre-channel cancellation); all real-time, all in WebAssembly, no AI; works on any tab incl. YouTube, Spotify Web, SoundCloud; Chrome/Edge/Brave/Arc/Vivaldi/Opera; free; MIT; 347 users, 5.0/5 (5 ratings), v1.4.0 updated 2026-09-02, 157 KiB — [Karafilt site](https://karafilt.com/); [Chrome Web Store](https://chromewebstore.google.com/detail/eiclobknpdiipnhdpfpegfnkplmfnmoo)
- "Turn YouTube into Karaoke (Lyrics + Vocal Reduction)": real-time vocal reduction plus synced lyrics; detects mono tracks "needing AI processing" to save credits; free standard mode; 2 ratings — [Chrome Web Store](https://chromewebstore.google.com/detail/bdkplajjapollcjnlkgilhecfkodpgii)
- EasyKaraoke: local real-time processing with a 1500 Hz notch to clean leftover vocal resonance — [Chrome Web Store](https://chromewebstore.google.com/detail/mjojifgeknmamhpankmgpgliacbigmeg); "YouTube Karaoke: AI Vocal Removal & Live Lyrics" — [Chrome Web Store](https://chromewebstore.google.com/detail/youtube-karaoke-extension/nephnenkcakiaiejolafiiiefcdikjaj); Karaoke Monster (lyrics + voice removal + EQ) — [Chrome Web Store](https://chromewebstore.google.com/detail/karaoke-monster/impekelmmfmbnjfjadmjnfclgkacaekn)
- Firefox: "Tab Audio Recorder" captures media elements / stream URLs / page AudioContext (page-level, no tabCapture) — [AMO](https://addons.mozilla.org/firefox/addon/tab-audio-rec/); "CB Capture" recorder is available on Firefox for Android — [AMO](https://addons.mozilla.org/addon/cb-capture/)

### Inferences
- Both of the ML-based music/vocal extensions (NoMusic, Wakapippi) and the DSP one (Karafilt) are single-developer projects with ≤1,000 users each; there is no evidence of a widely adopted real-time music-removal extension as of Nov 2026.
- NoMusic's choice of a *speech-enhancement* model (FastEnhancer) rather than a separation model implies it treats music as "noise"; its 4.8 rating from 34 users suggests this is acceptable to its audience, but no independent quality test exists.

### Gaps
- Listings for "Ears: Bass Boost, EQ Any Audio" (ID nndicbfeobcndaafhhdiphpnbkeohjan), "Volume Master", "Audio Equalizer" and "Sound Booster" could not be loaded (Chrome Web Store returned only navigation; chrome-stats mirror returned 403), so their capture technique and user counts are not documented here.
- No Chrome Web Store user counts or techniques verified for the karaoke extensions beyond listing text.

## Key question B3 — "Halal" / no-music browser extensions: what exists and how they work

### Takeaway
At least five Muslim-targeted "remove music" extensions exist (HaramMute, MusicRemover/IqraWave, Halalify, NoMusic, Halal YT Music Filter); apart from NoMusic (in-browser AI) they either pre-process the video on a server (HaramMute: "Preparation requires an internet connection") or rely on a native companion app reached over localhost (MusicRemover port 56348; HaramMute ports 8765–8768; Halalify "Companion" app), and all are YouTube-first with tiny user bases (48–1,000).

### Cited Findings
- HaramMute (Chrome + Firefox incl. Android; iOS/Android apps): "works in the background to reduce or remove music while keeping speech as clear as possible"; YouTube "Active", other platforms "Coming Soon"; pre-recorded videos only, not live streams; website says it "processes the video links you choose to provide clean audio" and "Preparation requires an internet connection", "Preparation time varies by video"; free tier 60 min/week on videos ≤15 min, paid plans for more; "targets music specifically" — [haram-mute.com](https://haram-mute.com/); Firefox/Android listing: 452 users, 5/5 (3 reviews), v1.0.6 (4.84 MB) updated 2026-04-26; required host www.youtube.com; optional localhost/127.0.0.1 ports 8765–8768, api.haram-mute.com, PostHog analytics; developer declares collecting PII and website activity; All Rights Reserved — [AMO Android listing](https://addons.mozilla.org/en-US/android/addon/harammute/)
- MusicRemover / "Haram Music Remover for YouTube" by Iqra Wave (Firefox): v2.5.0; requires the free desktop app from musicremover.org/pc-app (Windows or Linux); optional permission localhost:56348; "AI-powered vocal isolation" on-device, no uploads/accounts; "fast local caching for instant replay after first processing"; YouTube only; 48 users, 0 reviews, updated 2026-10-13; All Rights Reserved; free but "Some features may require payment" — [AMO listing](https://addons.mozilla.org/en-US/firefox/addon/haram-music-remover/); musicremover.org pages returned only a title ("Mute Haram Music on YouTube & Any Video | Free") — [musicremover.org](https://musicremover.org/)
- Halalify (Chrome): "AI-powered audio filter" that "detects and mutes background music tracks in real-time, leaving only the dialogue"; requires a separate free "Halalify Companion" app; works on "your favorite video platforms" (none named); 233 users, 5.0/5 (2 ratings), v1.7 updated 2026-02-03; developer "azex"; privacy policy at halalify.net/privacy — [Chrome Web Store](https://chromewebstore.google.com/detail/halalify/kkmnioioinpnnebdbgfaabagojibhpok); halalify.net returned only its title — [halalify.net](https://halalify.net/)
- NoMusic (Chrome): in-browser real-time AI, "any video", ~1,000 users, open source — [Chrome Web Store](https://chromewebstore.google.com/detail/fepfnjijcojaoihcekfhonohejglmdbc)
- Halal YT Music Filter (Firefox): hides songs/playlists/recommendations on YouTube Music that do not match Quran-related keywords (content filtering, not audio processing) — [listing mirror](https://firefox.marketplace.browsertotal.com/en-US/firefox/addon/halal-yt-music-filter)

### Inferences
- The "extension + native companion over localhost" pattern (MusicRemover, Halalify, HaramMute's optional local ports) is how these projects escape browser compute/latency limits: the native app runs a Demucs/UVR-class model and the extension only swaps or syncs audio. HaramMute's server-side "preparation" (not live, YouTube only, minutes-limited) and NoMusic's lighter speech-enhancer are the two alternative trade-offs.
- None of these covers Instagram, TikTok or Netflix web today per their own listings; "any video" claims (NoMusic, Halalify) are unverified.

### Gaps
- Which models MusicRemover, Halalify and HaramMute use, their latency, and whether they are truly real-time versus first-play pre-processing could not be determined (sites return only titles; listings are self-reported).
- HaramMute's Chrome Web Store listing and user count were not retrieved.
