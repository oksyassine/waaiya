# Always-on, system-wide background audio processor on Windows and macOS (intercept all app output, strip instruments, keep voice, play only processed audio) — state as of Nov 2026

Research note: WebSearch budget ran out mid-task; all later work used direct fetches of known URLs. Items that could not be verified are listed under Gaps rather than asserted.

## W1. Windows — Equalizer APO as a ready-made system-wide hook (scope, exclusive mode, VST filter limits, DRM/signing)

### Takeaway
Equalizer APO is a free, unsigned Audio Processing Object that installs itself per output endpoint (pre-mix and/or post-mix stage) and processes every shared-mode WASAPI/DirectSound stream on that device; it does NOT see WASAPI-exclusive streams or vendor hardware OpenAL, only loads because the installer sets `DisableProtectedAudioDG=1`, and its VST filter is limited to 64-bit VST 2.x DLLs running inside `audiodg.exe` under the LocalService account. A 2026 third-party report claims the `DisableProtectedAudioDG` override no longer works on current Windows 11 builds, which if true undermines the whole unsigned-APO route.

### Cited Findings
- Equalizer APO is "A system-wide equalizer for Windows 7 / 8 / 8.1 / 10 / 11"; the installer runs a Configurator where you pick the audio device to attach the APO to, and a reboot is recommended because the APO only takes effect after the audio service restarts — [Equalizer APO Documentation (SourceForge wiki)](https://sourceforge.net/p/equalizerapo/wiki/Documentation/)
- Some drivers disable features when they detect another APO; unchecking one "Install APO" box installs Equalizer APO only at the pre-mix or post-mix stage, leaving the original APO at the other stage; "troubleshooting mode" lets you uncheck both "Use original APO" boxes at the cost of driver features — [Equalizer APO Documentation](https://sourceforge.net/p/equalizerapo/wiki/Documentation/)
- `Stage` command: output devices have two stages, pre-mix and post-mix; input devices have only a capture stage; default is post-mix + capture so filters run once per device; "Post-mix is preferred because pre-mix filtering runs per application and uses more CPU" — [Equalizer APO Configuration reference](https://sourceforge.net/p/equalizerapo/wiki/Configuration%20reference/)
- Equalizer APO does not process WASAPI exclusive-mode streams: "If a program uses WASAPI in Exclusive mode, it bypasses the win-audio stack"; "WASAPI Exclusive mode bypasses all Windows Audio Processing Objects—the 'APO' in EqualizerAPO"; shared-mode WASAPI and DirectSound are processed — [Hydrogenaudio thread](https://hydrogenaud.io/index.php/topic,125173.0.html); [AVNirvana "eqAPO has no effect on REW"](https://www.avnirvana.com/threads/eqapo-has-no-effect-on-rew.13263); [WhatHiFi Qobuz thread](https://forums.whathifi.com/threads/free-equalizer-app-that-works-with-qobuz.117250/post-1254389)
- Hardware-accelerated OpenAL (vendor OpenAL libraries) bypasses APOs and "there's no way to enable APO support for them"; workaround is forcing software OpenAL — [Equalizer APO Documentation](https://sourceforge.net/p/equalizerapo/wiki/Documentation/)
- Equalizer APO can only process uncompressed audio (undecoded Dolby Digital bitstreams can't be processed) — [Equalizer APO Documentation](https://sourceforge.net/p/equalizerapo/wiki/Documentation/)
- DRM: per a developer comment, the `DisableProtectedAudioDG` registry entry is required because "Equalizer APO is unsigned, so it breaks the protected audio path. DRM software that checks that path may output no sound." — [Equalizer APO Documentation](https://sourceforge.net/p/equalizerapo/wiki/Documentation/)
- Developer docs: the DWORD `DisableProtectedAudioDG` under `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Audio` must be set to 1 "so that the signature check is skipped and unsigned APOs load" — [Equalizer APO Developer documentation](https://sourceforge.net/p/equalizerapo/wiki/Developer%20documentation/)
- Conflicting 2026 report: the Veyra project states the flag "no longer disables the protection on recent Windows 11 builds"; tested on build 26200.8655 (2026-07-01): "Even with the flag set and after a full reboot, audiodg started protected and rejected the unsigned DLL"; "Do not rely on this flag." `audiodg.exe` "runs as a protected process and loads only digitally signed APO DLLs"; test-signing alone isn't enough — [Veyra v1.0.0 release notes](https://github.com/NextGenDev-KSK/veyra/releases/tag/v1.0.0) (single project, unverified elsewhere)
- Error log is written to `C:\Windows\ServiceProfiles\LocalService\AppData\Local\Temp\EqualizerAPO.log` (i.e., the APO executes under the LocalService profile) — [Equalizer APO Documentation](https://sourceforge.net/p/equalizerapo/wiki/Documentation/)
- VST filter: "EQ APO can only load 64-bit VST2 DLLs - not VST3/AU/CLAP/etc."; Steinberg's license no longer allows new developers to create VST2 plug-ins — [itch.io post by MiniMeters developer](https://itch.io/post/11306876)
- "a 32 bit version of a plugin can't be used on a 64 bit Windows pc"; loading soothe2 crashed the Configuration Editor; "The plugin might use some files located in folders to which Equalizer APO has no right to read" — [SourceForge ticket #221 "Crash with VST2 plugin loaded"](https://sourceforge.net/p/equalizerapo/tickets/221)
- Community fork equalizerAPO64 (TheFireKahuna) adds double-precision processing, says VST2s with native double precision are "now properly supported", and "Requires at minimum a CPU with AVX2 support" — [equalizerAPO64 release 1.4.2_2](https://github.com/TheFireKahuna/equalizerAPO64/releases/tag/1.4.2_2)
- A StereoTool forum user reported plugin GUIs "don't appear to work in this plugin host, and it crashes upon trying to spawn the GUI a second time" — [StereoTool forum](https://forums.stereotool.com/viewtopic.php?p=65424)
- Roon community user: Equalizer APO's troubleshooting mode can disable the stock Windows APOs for bit-perfect shared-mode WASAPI (user report) — [Roon community](https://community.roonlabs.com/t/possible-to-disable-exclusive-mode-over-wasapi/247914)

### Inferences
- Because the APO executes inside `audiodg.exe` as LocalService, a VST (or any ML code) hosted by Equalizer APO cannot read per-user files, has no user-session GUI, and must satisfy the audio engine's real-time constraints; a heavy ML separation model inside it is therefore risky (GUI crashes and file-permission crashes in the sources are symptoms of this environment).
- Exclusive-mode players (foobar2000/Qobuz/Tidal/Roon in exclusive, some games/ASIO apps) and hardware OpenAL will reach the speaker unprocessed, violating the "user hears nothing unprocessed" requirement unless the app is forced to shared mode.
- If the Veyra report about `DisableProtectedAudioDG` is correct, Equalizer APO (and any unsigned APO) stops loading on current Windows 11; the Veyra author's fallback is exactly the virtual-cable/loopback "bridge" pattern in W3.

### Gaps
- No official Equalizer APO wiki page documenting the VST filter's limits was reachable (the Configuration reference page fetched did not contain a VST section); the "64-bit VST2 only" statement comes from a plugin developer and ticket reports, not the project author.
- Could not independently confirm whether `DisableProtectedAudioDG` still works on Windows 11 24H2/25H2 GA builds; only the Veyra claim (Insider-looking build 26200.x) was found.
- No measured latency figure for Equalizer APO itself was found (its own docs only give latency for Convolution: linear-phase IRs add half the IR length).

## W2. Windows — Writing a custom APO (signing, SFX/MFX/EFX, real-time rules, feasibility of running an ML model or calling a user-mode service)

### Takeaway
A custom APO is an in-process COM DLL loaded into the protected `audiodg.exe`; it must be installed as a component of a specific audio device's driver package (no global APOs since the 1809 componentized model), must be properly signed to survive protected-content graphs, and must obey hard real-time rules (non-blocking, non-paged, "should not introduce significant latency"), which makes hosting an ML separation model or blocking IPC to a user-mode service inside the APO contrary to Microsoft's design rules.

### Cited Findings
- APOs are "COM-based, real-time, in-process objects" running in user mode inside the audio engine; there are three placements: Stream (SFX, per stream, before the mix), Mode (MFX, per processing mode, after the mix), Endpoint (EFX, "always applied, even to raw streams"); "Windows 10 loads RAW MFX but not RAW SFX" — [Microsoft Learn: Audio Processing Object Architecture](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/audio-processing-object-architecture)
- "Each logical device can be associated with one APO of each type." Required interfaces: `IAudioProcessingObject`, `IAudioProcessingObjectConfiguration`, `IAudioProcessingObjectRT` (APOProcess, callable from a real-time thread), `IAudioSystemEffects` — [Microsoft Learn: Implementing APOs](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/implementing-audio-processing-objects)
- Real-time rules: "All methods that are members of real-time interfaces must be implemented as nonblocking members. They must not block, use paged memory, or call any blocking system routines. All buffers that are processed by the APO must be nonpageable... APOs should not introduce significant latency into the audio processing chain." — [Microsoft Learn: Implementing APOs](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/implementing-audio-processing-objects)
- Default base class `CBaseAudioProcessingObject` "operates on the required float32 format" — [Microsoft Learn: Implementing APOs](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/implementing-audio-processing-objects)
- Signing/protected environment: with an embedded manifest "your APO will run with DisableProtectedAudioDG=1, but when this test key is removed, your APO will fail to load, even if it is WHQL-signed." A primary `CoCreateInstance` failure reason is "The graph is running protected content, and the APO is not properly signed." After 10 load failures the system disables all SysFx on the endpoint via `PKEY_Endpoint_Disable_SysFx` — [Microsoft Learn: Implementing APOs](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/implementing-audio-processing-objects)
- Installation: "Starting with Windows 10, release 1809, APO registration with the audio engine uses the componentized audio driver model"; the APO device "must be a PNP child of the audio device"; "The new componentized APO design does not allow for an APO to be registered globally and used by multiple different drivers. Each driver must register its own APO's." INF keys: `PKEY_FX_StreamEffectClsid`, `PKEY_FX_ModeEffectClsid`, `PKEY_FX_EndpointEffectClsid`, `PKEY_SFX/MFX/EFX_ProcessingModes_Supported_For_Streaming`; INF class `AudioProcessingObject` GUID `{5989fce8-9cd0-467d-8a6a-5419e31529d4}` — [Microsoft Learn: Implementing APOs](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/implementing-audio-processing-objects)
- EFX streaming caveat: in the SYSVAD sample, `PKEY_EFX_ProcessingModes_Supported_For_Streaming` is commented out "because the audio processing has transitioned to kernel mode above that layer... the mode mix / tee happens lower in the stack, where it is not possible to insert an endpoint APO" — [Microsoft Learn: Implementing APOs](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/implementing-audio-processing-objects)
- Developer experience (OSR, 2019): an APO signed with an EV certificate and submitted for attestation signing still failed to load in protected `audiodg.exe` (Event 6281 "page hashes of an image file are not valid"); community expert Tim Roberts: APOs "must be tied to a specific audio device and installed with that device's driver package" and "general purpose" APOs are "a direct contradiction of Microsoft's guidelines" — [OSR Community: APO Signing and Installation](https://community.osr.com/t/apo-signing-and-installation/55812)
- Reference sample: SYSVAD SwapAPO (SFX + MFX, swaps L/R) in the Windows driver samples repo — [Microsoft Learn: Implementing APOs](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/implementing-audio-processing-objects)
- Effects discovery API: `Windows.Media.Effects.AudioRenderEffectsManager.GetAudioRenderEffects()` lists effects on a render device and raises `AudioRenderEffectsChanged`; lower-level `IAudioEffectsManager::GetAudioEffects` returns `AUDIO_EFFECT` structures per stream, with `IAudioEffectsChangedNotificationClient` for changes — [Microsoft Learn: AudioRenderEffectsManager](https://learn.microsoft.com/en-us/uwp/api/Windows.Media.Effects.AudioRenderEffectsManager); [IAudioEffectsManager::GetAudioEffects (sdk-api docs source)](https://github.com/MicrosoftDocs/sdk-api/blob/docs/sdk-api-src/content/audioclient/nf-audioclient-iaudioeffectsmanager-getaudioeffects.md); [Audio effects discovery sample](https://github.com/microsoftarchive/msdn-code-gallery-microsoft/tree/411c271e537727d737a53fa2cbe99eaecac00cc0/Official%20Windows%20Platform%20Sample/Audio%20effects%20discovery%20sample)

### Inferences
- A shipping custom APO for "every output device the user might plug in" (USB DAC, Bluetooth, HDMI) is structurally impossible under the componentized model: the APO must ride on a specific device's driver package, so a general-purpose, device-agnostic ML APO is not a supported configuration.
- Running an ONNX/DirectML model inside `APOProcess` conflicts with the non-blocking/non-paged rules and with running inside protected `audiodg.exe` as LocalService; the realistic design is an APO that only does lightweight DSP, or (preferred) moving ML to a user-mode app via W3.
- An APO cannot "call into a user-mode service" synchronously without blocking; any IPC would have to be lock-free shared memory with the ML result arriving late, which is equivalent to the loopback/bridge design anyway.

### Gaps
- No Microsoft page explicitly spelling out "APO DLL must be attestation/WHQL signed on Windows 11" was found; the requirement is inferred from the protected-content failure text and the OSR thread. Exact Partner Center submission path for an APO-only package was not found.
- No source on whether GPU (DirectML/CUDA) or NPU access is possible from inside `audiodg.exe`.

## W3. Windows — Virtual audio cable / loopback + user-mode processing (VB-CABLE, Voicemeeter, SAR; WASAPI loopback; process loopback; why loopback alone is not enough; latency)

### Takeaway
The robust Windows design is: make a virtual render endpoint the default device, capture it (WASAPI loopback or the cable's capture side) in a user-mode app, run ML, and render to the real device. Plain WASAPI loopback cannot be the whole answer because, per Microsoft, loopback copies the engine's output "in addition to" sending it to the hardware, so the user would hear the unprocessed original; process-loopback (Win10 20348+) likewise captures without muting. Voicemeeter's Virtual ASIO Insert adds exactly one buffer of latency; SAR runs at 1–2 ms buffers but is unsigned/stale.

### Cited Findings
- WASAPI loopback: open a capture stream on the render endpoint with `AUDCLNT_STREAMFLAGS_LOOPBACK`; "A client can enable loopback mode only for a shared-mode stream (AUDCLNT_SHAREMODE_SHARED). Exclusive-mode streams cannot operate in loopback mode." — [Microsoft Learn: Loopback Recording](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)
- Original still plays: "When the hardware does not support a loopback pin, WASAPI copies the output stream from the audio engine into the loopback application's capture buffer, in addition to copying the audio data to the hardware's render pin." — [Microsoft Learn: Loopback Recording](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)
- Event-driven loopback clients are supported in Windows 10 1703+; earlier versions needed a dummy render stream — [Microsoft Learn: Loopback Recording](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)
- DRM: "a trusted audio driver does not permit a loopback device to capture digital streams that contain protected content" — [Microsoft Learn: Loopback Recording](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)
- Service use: "WASAPI loopback by default contains the mix of all audio being played, regardless of the Terminal Services session... you can run a loopback client in a service running in session 0 and capture audio from all user sessions" — [Microsoft Learn: Loopback Recording](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)
- Process loopback: `AUDIOCLIENT_PROCESS_LOOPBACK_PARAMS` (header `audioclientactivationparams.h`) with `TargetProcessId` and `ProcessLoopbackMode` (include or exclude the process tree), passed to `ActivateAudioInterfaceAsync`; minimum Windows 10 Build 20348 — [Microsoft Learn: AUDIOCLIENT_PROCESS_LOOPBACK_PARAMS](https://learn.microsoft.com/en-us/windows/win32/api/audioclientactivationparams/ns-audioclientactivationparams-audioclient_process_loopback_params)
- ApplicationLoopback sample: captures "only audio from the specified process, and its children" (or everything except that tree); not tied to one endpoint; if the target renders nothing you get silence; usage `ApplicationLoopback 1234 includetree Captured.wav` — [Windows-classic-samples/ApplicationLoopback](https://github.com/microsoft/Windows-classic-samples/tree/main/Samples/ApplicationLoopback)
- Existence proof of the bridge pattern: Veyra's "Audio Bridge" runs the DSP chain inside a service that "loopback-captures a source device and renders the processed audio to the output device"; "It needs no driver signing and is the only working option for Bluetooth A2DP endpoints." — [Veyra v1.0.0 release notes](https://github.com/NextGenDev-KSK/veyra/releases/tag/v1.0.0)
- Voicemeeter Banana (v2.1.3.0, package dated Sept 2026): two virtual I/O devices (virtual input up to 8 ch) over MME/DirectX/KS/WDM/WaveRT at 8–192 kHz; "Virtual ASIO Insert" with 22 channels in/out for a single client app, sample rate and buffering taken from Main Output A1; supports Windows XP–11 incl. ARM64; donationware — [VB-Audio Voicemeeter Banana](https://vb-audio.com/Voicemeeter/banana.htm)
- VB-Audio staff: the Virtual ASIO Insert runs at the same rate/buffer as the main stream and "adds one buffer" (e.g., 128 + 128 samples at a 128-sample buffer) — [VB-Audio forum, "Question about ASIO buffer"](https://forum.vb-audio.com/viewtopic.php?p=4232); virtual-input internal latency must exceed 3× the main buffer or virtual inputs may drop out — [VB-Audio forum](https://forum.vb-audio.com/viewtopic.php?p=739); a host used through the insert adds its own latency on top — [Cantabile community](https://community.cantabilesoftware.com/t/please-add-voicemeeters-audio-callback-integration/6672)
- Synchronous Audio Router (open source): creates virtual Windows endpoints exposed as ASIO channels, clock-synced to a physical interface; uses WaveRT so "1-2ms buffer sizes on a cheap USB 2.0 interface are practical"; endpoints exist only while the host has ASIO running; can override the default device per app with regex rules; "Secure Boot does not work on current Windows 10"; prerelease builds are unsigned and need test-signing — [eiz/SynchronousAudioRouter](https://github.com/eiz/SynchronousAudioRouter); AlternativeTo lists it as discontinued with last version 0.13.1 (April 2018) — [AlternativeTo](https://alternativeto.net/software/synchronous-audio-router/about)
- NVIDIA Broadcast's speaker path is the same pattern: it "creates virtual devices"; you select "Speaker (NVIDIA Broadcast)" in apps; NVIDIA warns against making it the Windows default because it would filter "all audio coming through your device, such as videos and music" — [NVIDIA Broadcast setup guide](https://www.nvidia.com/en-us/geforce/guides/broadcast-app-setup-guide/)
- Krisp likewise asks you to select "Krisp Speaker" as the output in the conferencing app — [Krisp noise cancellation page](https://krisp.ai/noise-cancellation/)

### Inferences
- The "user hears nothing unprocessed" requirement forces the default-device-is-a-virtual-sink design on Windows; neither loopback nor process-loopback mutes the source. Exclusive-mode apps that open the virtual sink in exclusive mode would still be captured (the sink's capture side sees them), which is an advantage over the APO route — but apps hard-wired to a specific physical device bypass everything.
- Veyra's note that the bridge is "the only working option for Bluetooth A2DP endpoints" implies the APO route is not viable on Bluetooth A2DP on current Windows.
- Expected added latency for a cable+ML bridge = capture period + model lookahead/hop + render buffer; with 10 ms shared-mode periods on both sides this is roughly 20–30 ms plus model latency (no primary source found for the exact WASAPI figures — see Gaps).

### Gaps
- No primary source found for WASAPI shared-mode default period (10 ms) or `IAudioClient3` low-latency minimums; latency arithmetic above is an inference.
- VB-CABLE and Virtual Audio Cable (Muzychenko) specific latency numbers were not retrieved.
- No source on whether a Session-0 Windows service can reliably *render* to the user's default device (only loopback capture from session 0 is documented).
- `AudioGraph` and `ISpatialAudioClient` were not researched (budget exhausted).

## W4. Windows — Windows Studio Effects (Voice Focus / Voice Clarity), NPU effects: output-side or mic-only?

### Takeaway
Microsoft's own documentation defines Voice Focus as a microphone (capture) effect of Windows Studio Effects running on NPUs of opted-in devices (Windows 11 22H2 build 22623.885+); no Microsoft-provided NPU effect for the speaker/render path was found, and third-party guides that place Voice Focus on the playback device conflict with Microsoft's text.

### Cited Findings
- "Supported Windows Studio Effects for the integrated microphone, include: Voice Focus: A microphone effect designed to filter out background noise"; prerequisites "Windows 11, version 22H2 or newer (Build 22623.885+)" and a supported NPU with the OEM having installed the Windows Studio Effects driver; effects are "applied at the hardware level for the camera (or microphone)" via Kernel Streaming properties — [Microsoft Learn: Windows Studio Effects Overview](https://learn.microsoft.com/en-us/windows/apps/develop/windows-integration/studio-effects)
- Conflicting third-party guide: Thurrott's Field Guide says Voice Focus is configured under the default *playback* device's "Audio enhancements" — [Thurrott Windows 11 Field Guide](https://www.thurrott.com/books/windows-11-field-guide/hardware-windows-11-field-guide/296496/windows-studio-effects); Pureinfotech and Geekrewind say pick the microphone — [Pureinfotech](https://pureinfotech.com/?p=172045); [Geekrewind](https://geekrewind.com/how-to-enable-or-disable-voice-focus-to-reduce-microphone-background-noise-in-windows-11/)
- Voice Clarity is separate from Voice Focus; "these are features for input devices" and it "works automatically on supported devices without any settings to configure" — [Pureinfotech](https://pureinfotech.com/?p=172045)
- Voice Focus is described as a noise-cancellation feature of Windows Studio Effects in Windows 11 24H2+, requiring a Copilot+ PC NPU for the latest update — [ElevenForum](https://www.elevenforum.com/t/enable-or-disable-voice-focus-to-reduce-microphone-background-noise-in-windows-11.28477)

### Inferences
- Windows has no built-in system-wide "speaker voice isolation" API that a third party can enable; Studio Effects are OEM-opted KS properties on the mic/camera, not a hookable render pipeline.

### Gaps
- Could not fetch Microsoft's consumer support page for Voice Clarity to confirm its scope and hardware (Arm/Snapdragon vs x86).

## W5. Windows — Existing products that process SPEAKER/OUTPUT audio with ML in real time (existence proofs) and whether they remove music

### Takeaway
Several shipping products already run real-time ML on the output path system-wide via a virtual speaker device (NVIDIA Broadcast "Speakers", Krisp "Speaker", SteelSeries Sonar Chat), and Moises Live (Windows + macOS, Microsoft Store/App Store) is the closest existence proof of the exact goal: on-device, real-time separation of all system audio into dialogue/effects/instruments. Noise-suppression products target noise, not music, but Tom's Hardware found NVIDIA Broadcast removed a background theme song entirely.

### Cited Findings
- Moises Live: a desktop app for Windows and macOS that "runs entirely on-device and works offline", processes "your system's audio signal in real-time", separates system audio into "dialogue, effects, and instruments", works "with any app, from browsers to media players and editors", downloadable from the Microsoft Store or Apple App Store; the page says the original Moises app delivers higher-quality separation — [Moises Live product page](https://moises.ai/live/); help article describes Music and Speech presets for streaming content but was inconsistent about Mac availability — [Moises Live help (search snippet; page returned 403 on fetch)](https://help.moises.ai/hc/en-us/articles/20126450906908-Moises-Live)
- NVIDIA Broadcast app: current listing 2.3.0; requires GeForce RTX 2060 / Quadro RTX 3000 / TITAN RTX or higher; audio effects "Studio Voice", "Noise Removal", "Room Echo Removal"; also a "File Processor" and an "MCP Server"; no latency stated — [NVIDIA Broadcast app page](https://www.nvidia.com/en-us/geforce/broadcasting/broadcast-app/)
- NVIDIA Broadcast speaker effects work via a virtual "Speaker (NVIDIA Broadcast)" device; setting it as Windows default "would filter all system sounds" — [NVIDIA Broadcast setup guide](https://www.nvidia.com/en-us/geforce/guides/broadcast-app-setup-guide/)
- Music removal evidence: Tom's Hardware played a children's show theme song in the background and Broadcast was "removing all the music and vocals", with the voice "a little less full" — [Tom's Hardware test](https://www.tomshardware.com/news/nvidia-broadcast-tested); Engadget: the strength slider "doesn't seem to fade out sounds like music, instead it falls off only once you apply the maximum amount" — [Engadget](https://www.engadget.com/nvidia-broadcast-is-kinda-underrated-141026195.html?src=rss); TechRadar warns that if set as default device "all audio types (such as music or videos) will have Broadcast effects applied" — [TechRadar](https://www.techradar.com/how-to/how-to-use-nvidia-broadcast-to-improve-your-webcam-and-microphone)
- NVIDIA Maxine Audio Effects (AFX) SDK (docs last updated Sep 22 2026): effects are Audio Super-Resolution, Noise Removal, Noise Removal + Room Echo Removal (combined), Room Echo Removal, Speaker Focus (isolates prominent speaker from background speakers), Studio Voice; AEC and Voice Font deprecated; Windows SDK supports x64 and Windows-on-Arm (N1X) and is "optimized for client-side application integration"; there is no music-removal effect — [NVIDIA AFX SDK User Guide](https://docs.nvidia.com/maxine/afx/latest/index.html); sample app runs at 16 kHz or 48 kHz — [NVIDIA MAXINE-AFX-SDK GitHub](https://github.com/NVIDIA/MAXINE-AFX-SDK)
- Krisp: removes "background noises, voices and echoes" in real time; "Cancel others' noise" mode targets noise from other participants (listener-side); setup uses "Krisp Microphone" and "Krisp Speaker" virtual devices; music not mentioned — [Krisp noise cancellation](https://krisp.ai/noise-cancellation/); a secondary guide warns "Music, television, singing, and unusual speech can also be misclassified" — [Geekchamp Krisp guide](https://geekchamp.com/?p=1072034)
- SteelSeries Sonar ClearCast AI: mic noise cancellation in GG Sonar, with a Chat-category option to "filter out incoming noise from your teammates"; "does not use the GPU, only the CPU"; requires GG running in background — [SteelSeries blog](https://steelseries.com/en-si/blog/how-to-eliminate-noise-from-microphone-communication-869); one user reported Discord voices became distorted until ClearCast AI was disabled — [r/steelseries](https://redlib.belloworld.it/r/steelseries/comments/1c2g3au/sonar_is_garbage/kza1rh7/?context=3)
- AudioShake SDK (vendor claims): real-time dialogue isolation with "11ms dialogue isolation latency" (Dialogue RT), on-device inference "under 50ms latency or better", models "as small as 9mb", platforms iOS/macOS, Android, Windows, Linux; a music-removal product "removes copyrighted background music from live or streamed audio while preserving dialogue and effects"; licensing by contact — [AudioShake SDK](https://www.audioshake.ai/products/sdk)
- Plug-in (not system-wide) real-time dialogue isolators exist for Mac/Windows: Audionamix IDC (Instant Dialogue Cleaner) and Acon Digital Extract:Dialogue 2 — [SoundStoreXL listing](https://www.soundstorexl.com/products/extract-dialogue); [Vintage King listing](https://vintageking.com/software/acon-digital-extract-dialogue-noise-reduction-plug-in-electronic-delivery)
- Open-source direction: "poise-voice-isolator" has a PR adding macOS support via Core Audio process taps — [chabandou/poise-voice-isolator PR #47](https://github.com/chabandou/poise-voice-isolator/pull/47)
- Veyra (open source, 2026): APO + service "Audio Bridge" DSP for Windows (existence proof of the bridge architecture) — [Veyra v1.0.0](https://github.com/NextGenDev-KSK/veyra/releases/tag/v1.0.0)

### Inferences
- Moises Live demonstrates that an OS-integrated, on-device, real-time music/dialogue separator shipping through the Microsoft Store and Mac App Store is feasible in 2026; its "works with any app" wording implies a virtual-device (Windows) / tap-or-driver (macOS) capture, but the vendor does not disclose the mechanism.
- Noise suppressors (NVIDIA/Krisp/Sonar) are trained to keep speech and discard everything else, so they do remove much music, but with no guarantee and with audible voice thinning; a dedicated speech/music separation model (AudioShake-class) is the right tool.

### Gaps
- Moises Live's capture mechanism, latency, and whether it mutes the original signal are undocumented.
- No official Krisp statement on music was found. Dolby Access/Atmos "Dialogue Enhancer", DTS "Dialog Control", Nahimic, Waves MaxxAudio, Voicemod and Samsung "Active Voice Amplifier" could not be researched (search budget exhausted).
- No measured latency figures for NVIDIA Broadcast or Krisp speaker effects were found.

## M1. macOS — Core Audio Taps (API, mute behaviour, OS version, TCC permission, global tap, real-time re-output)

### Takeaway
Core Audio process taps (macOS 14.2+) let an app capture the output of any process or of all processes (`CATapDescription(stereoGlobalTapButExcludeProcesses: [])`), and `CATapMuteBehavior.muted` / `.mutedWhenTapped` silence the source's hardware output while the tap is read so only the app's re-rendered audio is heard; the tap is consumed through a private aggregate device driven by a real output device, needs `NSAudioCaptureUsageDescription` and a TCC "System Audio Recording" grant (no public API to query it), and has several known pitfalls (level attenuation scaling with output channel pairs, silent failure with zero buffers, sandbox fragility).

### Cited Findings
- Apple sample "Capturing system audio with Core Audio taps": a tap "can specify which outputs it captures from a process or group of processes, as well as different mixdown options (mono, stereo, and so on). Taps can be public... or private... Taps can also mute the process output so that the process will no longer play to the speaker or selected audio device, and all process output will go to the tap." Create with `CATapDescription` → `AudioHardwareCreateProcessTap(_:_:)`; destroy with `AudioHardwareDestroyProcessTap`; aggregate via `AudioHardwareCreateAggregateDevice`; add tap UID (`kAudioTapPropertyUID`) to `kAudioAggregateDevicePropertyTapList`; "ensure that you're using macOS 14.2 or later"; must include `NSAudioCaptureUsageDescription`; "The first time you start recording from an aggregate device that contains a tap, the system prompts you to grant the app system audio recording permission." (Page metadata lists availability "macOS 26.0" for the sample itself.) — [Apple Developer: Capturing system audio with Core Audio taps](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps)
- `CATapMuteBehavior` (default `CATapUnmuted`): `unmuted` = "Audio is captured by the tap and also sent to the audio hardware"; `muted` = "Audio is captured by the tap but no audio is sent from the process to the audio hardware"; `mutedWhenTapped` = "Audio is captured by the tap and also sent to the audio hardware until the tap is read by another audio client. For the duration of the read activity on the tap no audio is sent to the audio hardware." (Page metadata says macOS 13.0+, which conflicts with the 14.2 requirement stated in the sample article.) — [Apple Developer: CATapMuteBehavior](https://developer.apple.com/documentation/coreaudio/catapmutebehavior)
- `CATapDescription` properties used in Apple's sample: `name`, `processes`, `isPrivate`, `muteBehavior`, `isMixdown`, `isMono`, `isExclusive`, `deviceUID`, `stream` — [Apple sample article](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps)
- Global tap: `init(stereoGlobalTapButExcludeProcesses:)` "taps everything except the listed PIDs. Passing an empty list captures the global mixdown"; `isExclusive` is a direction flag (setting it false after the global-exclude initializer inverted behaviour and captured only the app's own PID); recommended deployment target macOS 14.4+ because earlier versions "fall into different TCC categories with different prompt copy"; TCC keys its record to the signing identity, so unsigned `xcodebuild` builds never show the prompt; reset with `tccutil reset SystemAudioCaptureRequests <bundle-id>`; author disabled App Sandbox because tap behaviour under sandboxing is "fragile"; on macOS 26 passing `nil` dispatch queue to the IOProc silently fails; aggregate must have a real output device as main sub-device (`kAudioAggregateDeviceMainSubDeviceKey`), tap as sub-tap with `kAudioAggregateDeviceTapAutoStartKey = true`, `kAudioAggregateDeviceIsPrivateKey = true`, `kAudioSubTapDriftCompensationKey`; `AVAudioEngine` cannot be retargeted to the tap aggregate (use `AudioDeviceCreateIOProcIDWithBlock`); test callbacks delivered 4800 frames every 100 ms as 48 kHz stereo Float32; stop order `AudioDeviceStop` → `AudioDeviceDestroyIOProcID` → `AudioHardwareDestroyAggregateDevice` → `AudioHardwareDestroyProcessTap` — [DGR Labs: Capturing System Audio on macOS in 2026](https://dgrlabs.co/blog/2026-04-25-capturing-system-audio-on-macos-in-2026.html)
- Objective-C global tap recipe: `[[CATapDescription alloc] initStereoGlobalTapButExcludeProcesses:@[]]`, `setMuteBehavior:CATapUnmuted`, `setPrivate:YES`, `setExclusive:YES`; aggregate with `kAudioSubTapUIDKey` + `kAudioSubTapDriftCompensationKey`; a private aggregate requires a private tap; with a 4-channel output device the tapped volume is halved (same bug in ScreenCaptureKit on 14.2), workaround: scale by channel count or tap a specific device — [sudara gist](https://gist.github.com/sudara/34f00efad69a7e8ceafa078ea0f76f6f)
- Apple forum: tapped level drops with the number of stereo output pairs on the target device (about −12 dB with four pairs) — [Apple Developer Forums thread 806799](https://developer.apple.com/forums/thread/806799); a tap "delivers all-zero buffers while system audio is audible" in long sessions on macOS 26.5 beta — [Apple Developer Forums thread 825780](https://developer.apple.com/forums/thread/825780)
- Permission: "there's no public API to request audio recording permission or to check if the app has that permission"; AudioCap uses private TCC calls — [insidegui/AudioCap](https://github.com/insidegui/AudioCap); the prompt now reads "System Audio Recording" (previously "Screen & System Audio Recording"); "every Core Audio API will return noErr even when permission is denied... your buffers contain zeros"; "AudioDeviceStart is what triggers the permission prompt" — [dev.to: 2000 buffers of nothing](https://dev.to/nickdelv/2000-buffers-of-nothing-3i8); `NSAudioCaptureUsageDescription` "tells people why your app is requesting access to capture system audio" — [Apple: NSAudioCaptureUsageDescription](https://developer.apple.com/documentation/bundleresources/information-property-list/nsaudiocaptureusagedescription)
- `.mutedWhenTapped` in practice: "macOS silences the app's direct hardware path only while the tap is being read"; "CATapMuted does not mute on its own; the tap must also be read. A tap nobody reads changes nothing"; without muting "you would hear the app twice"; a tap-only aggregate never runs IO because the output device drives the IO cycle — [ShutUpTheMac](https://github.com/oguzzkk/ShutUpTheMac); [tapmix](https://github.com/Sakuleta/tapmix); [companion-remote-volume issue #19](https://github.com/justereseau/companion-remote-volume/issues/19)
- Bindings/tools: Python `catap` (global tap of process output, exclude apps, set mute behaviour, can modify a running tap's mute behaviour) — [catap on PyPI](https://pypi.org/project/catap/0.5.1/); Rust crates `pocketstation` and `side-huddle` use `AudioHardwareCreateProcessTap` for global mono taps — [side-huddle record_tap.rs](https://docs.rs/crate/side-huddle/latest/source/src/platform/darwin/record_tap.rs)

### Inferences
- The exact architecture for this project on macOS is: global tap with `muteBehavior = .muted` (or `.mutedWhenTapped`), excluding the app's own PID so its re-rendered output isn't re-captured; aggregate device = real default output device + sub-tap; IOProc reads tap input, runs the model, writes to the output buffers in the same cycle. Because muting only takes effect while the tap is being read, any stall of the processing app un-mutes the raw audio (fail-open), which must be handled.
- The `.mutedWhenTapped` semantics mean the "nothing unprocessed is heard" guarantee is tied to continuous IOProc activity; using `.muted` is safer for the requirement but silences everything if the app crashes.
- DGR's 100 ms callbacks indicate the aggregate's buffer size must be explicitly set small (e.g., 128–512 frames) for low latency; the tap itself imposes no documented floor.

### Gaps
- Apple's `CATapDescription` reference page could not be fetched (JS-only); initializer names are taken from the DGR article, sudara gist and the Apple sample's property list.
- No Apple statement found on whether FairPlay/DRM-protected output (Safari Apple TV+/Netflix, Music app lossless/DRM) is delivered to a tap, or silenced — see M5.
- No measured end-to-end tap latency figure was found; the 100 ms figure is one author's default-buffer test, not a floor.

## M3. macOS — Virtual device / HAL (AudioServerPlugIn) projects and Rogue Amoeba's ACE stack as existence proofs

### Takeaway
Before taps, every system-wide macOS processor (Background Music, eqMac, BlackHole, Loopback, Audio Hijack/SoundSource via ACE) used a user-space `AudioServerPlugIn` virtual device set as default output, with the app pulling audio from the device's input side and re-rendering to the real device; this still works on macOS 26 but has well-documented fragility (device-switching, crash leaves system silent), and Rogue Amoeba itself moved to Apple's 2024 audio-permission (tap) path, with SoundSource 6.1.6 (macOS 15–27) applying Audio Units per-app and system-wide in real time.

### Cited Findings
- BlackHole: "a modern macOS virtual audio loopback driver that allows applications to pass audio to other applications" with "zero additional latency"; macOS 10.10+ (Intel and Apple Silicon); installed in `/Library/Audio/Plug-Ins/HAL` then `sudo killall -9 coreaudiod`; 2/16/64/128/256-channel builds; to hear and capture simultaneously you create a Multi-Output Device (BlackHole + speakers) in Audio MIDI Setup; GPL-3.0 — [ExistentialAudio/BlackHole](https://github.com/ExistentialAudio/BlackHole)
- Background Music: `BGMDriver` (virtual driver based on Apple's Core Audio User-Space Driver Examples) + `BGMApp`; on startup sets itself as default output and restores the previous device on quit; gets system audio from its virtual input (macOS treats it as a microphone, hence a mic-permission prompt); macOS 10.13+; v0.5.0, "still in alpha"; known issues: stereo-only, plugging/unplugging headphones while BGM isn't running can silence system audio, "If Background Music crashes, system audio may stop until you change the default output device", Chrome device-switch bug — [kyleneideck/BackgroundMusic](https://github.com/kyleneideck/BackgroundMusic)
- eqMac: driver is "a system audio loopback/passthrough device based on Apple's Null Audio Server Driver Plug-in example", "runs in User space instead of Kernel", passes audio to the app via a "secure memory tunnel"; AudioUnit hosting and per-app mixer are Pro features; public code v1.3.2 with newer releases on a private fork; Apache-2.0 — [bitgapp/eqMac](https://github.com/bitgapp/eqMac)
- Apple note quoted in a dev-forum thread: "Legacy Core Audio HAL audio hardware plug-ins are no longer supported. Use Audio Server plug-ins for audio drivers." (macOS 10.15) — [Apple Developer Forums thread 657619](https://developer.apple.com/forums/thread/657619)
- SystemEQ for Mac (open source, macOS 13+) uses BlackHole to "capture all system audio, process it, and send it back to your real output device" — [SystemEQ for Mac](https://denzam.github.io/SystemEQ-for-Mac/)
- Rogue Amoeba SoundSource 6.1.6 (Oct 26 2026), "For MacOS 15 to 27": built-in 10-band EQ, "Magic Boost", "Volume Overdrive", and Audio Unit support both per app and for all system audio — [Rogue Amoeba SoundSource](https://rogueamoeba.com/soundsource/)
- Audio Hijack 4.6.0 (Aug 27 2026), "For MacOS 14.4 to MacOS 27"; can record a specific app or "all the system audio at once"; local speech-to-text — [Rogue Amoeba Audio Hijack](https://rogueamoeba.com/audiohijack/)
- ACE history: macOS 11 betas (2020) broke ACE; "ACE as we knew it was dead in the water"; every replacement option "involved substantial reductions in functionality"; Apple later reversed course and "Earlier in 2024, Apple added audio permissions that let Rogue Amoeba ship a version of Audio Hijack that needs no installer or reboots" — [Six Colors summary](https://sixcolors.com/link/2024/12/the-long-strange-story-of-audio-hijack/) of [Rogue Amoeba weblog, Dec 13 2024](https://weblog.rogueamoeba.com/2024/12/13/the-developers-who-came-in-from-the-cold/)
- Tap-based per-app mixers now exist with "no virtual audio device, no driver, no change to your default output" — [ShutUpTheMac](https://github.com/oguzzkk/ShutUpTheMac); [tapmix](https://github.com/Sakuleta/tapmix); [dev.to volume-mixer write-up](https://dev.to/thalesbmc/macos-still-has-no-volume-mixer-so-i-built-one-53lp)

### Inferences
- The macOS 14.4 minimum of Audio Hijack and 15 minimum of SoundSource, together with "no installer or reboots", strongly indicate Rogue Amoeba's current ACE is built on Core Audio taps rather than a driver — so the taps route is production-proven for system-wide, real-time AU hosting.
- A virtual-device design remains the only option for macOS 13 and earlier and as a fallback if a tap returns zeros; it also lets exclusive/hog-mode-agnostic capture since everything targeted at the default device enters the driver.

### Gaps
- Rogue Amoeba's own ACE knowledge-base article could not be retrieved; its exact mechanism is inferred.
- Loopback (Rogue Amoeba) and Soundflower were not researched (budget).

## M5. macOS — Latency, reliability for always-on, device switching, DRM, sandbox/App Store, inference engines

### Takeaway
Latency on macOS is set by the aggregate device's buffer (taps and BlackHole claim no inherent added latency) plus model hop; reliability hazards are documented (tap level attenuation, silent zero buffers, crashes leaving system muted, headphone plug/unplug); taps need a stable signing identity and (per one practitioner) no App Sandbox, which conflicts with Mac App Store distribution; DRM behaviour under taps is undocumented, while Windows documents that protected streams are withheld from loopback.

### Cited Findings
- BlackHole claims "zero additional latency" — [BlackHole](https://github.com/ExistentialAudio/BlackHole); DGR's tap test ran at 4800 frames / 100 ms, 48 kHz stereo Float32 (default aggregate buffering, not a tuned value) — [DGR Labs](https://dgrlabs.co/blog/2026-04-25-capturing-system-audio-on-macos-in-2026.html)
- Reliability: tap all-zero buffers in long sessions (macOS 26.5 beta) — [Apple forum 825780](https://developer.apple.com/forums/thread/825780); level drop scaling with output pairs — [Apple forum 806799](https://developer.apple.com/forums/thread/806799); virtual-device approach: crash leaves system audio dead until default device is changed; headphone plug/unplug while app not running silences audio — [BackgroundMusic](https://github.com/kyleneideck/BackgroundMusic)
- Sandbox/signing: process taps "require a stable signing identity, since TCC keys its records to it"; author set `com.apple.security.app-sandbox = false` because CATap under sandboxing is "fragile", keeping Hardened Runtime for notarization — [DGR Labs](https://dgrlabs.co/blog/2026-04-25-capturing-system-audio-on-macos-in-2026.html)
- Moises Live ships through the Apple App Store and runs on-device — [Moises Live](https://moises.ai/live/)
- Windows DRM reference point: "a trusted audio driver does not permit a loopback device to capture digital streams that contain protected content" — [Microsoft Learn: Loopback Recording](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording); Windows APO reference point: unsigned APO is dropped when "The graph is running protected content" — [Microsoft Learn: Implementing APOs](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/implementing-audio-processing-objects)
- macOS DRM: only anecdotal claims found (a Reddit comment that Safari uses FairPlay and "dedicated security hardware to block audio and video capture"), no Apple documentation — [Reddit r/MacOS comment](https://twt.omada.cafe/r/MacOS/comments/1kpazvd/why_dont_most_people_use_safari/msz0bxq)

### Inferences
- Because Moises Live is on the App Store yet DGR reports tap fragility under sandbox, either Moises uses a sandbox-compatible path or has entitlements/exceptions; a LaunchAgent + notarized Developer-ID app outside the App Store is the lower-risk distribution for this project.
- For device switching (AirPods connect), the app must listen for `kAudioHardwarePropertyDefaultOutputDevice` changes and rebuild the aggregate (tear-down order per DGR) — switching is not automatic for a tap aggregate.
- Expect a Core ML/ANE or ONNX-CoreML model with a 10–20 ms hop to make total added latency in the 20–60 ms range at 128–512-frame buffers; this is an estimate, not a measured figure.

### Gaps
- No source found on how FairPlay-protected Safari/TV-app audio behaves under a global tap (silence vs. captured); must be tested.
- No measured glitch-free buffer-size numbers for tap-based processing on Apple silicon were found.
- LaunchAgent / login-item specifics for a tap-using daemon (whether TCC grants persist for a LaunchAgent, menu-bar app vs. agent) were not researched due to budget.
- Core ML vs ONNX Runtime CoreML EP vs PyTorch MPS real-time benchmarks were not researched.

## B2. Both OSes — Running as a background service that starts at login/boot

### Takeaway
On Windows, an APO starts automatically inside the audio engine, and Microsoft documents that a session-0 service can loopback-capture all sessions; the Veyra project runs its DSP bridge as a Windows service. On macOS, the tap/aggregate approach requires a signed app with a persistent TCC grant; practitioners run it as a menu-bar app, and the tap-based per-app mixers keep the default device untouched so nothing breaks if the app quits.

### Cited Findings
- "you can run a loopback client in a service running in session 0 and capture audio from all user sessions, as well as audio being played from session 0" — [Microsoft Learn: Loopback Recording](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)
- Veyra runs "the same DSP chain inside the service" that loopback-captures and renders; configured in `%ProgramData%\Veyra\config.json` — [Veyra v1.0.0](https://github.com/NextGenDev-KSK/veyra/releases/tag/v1.0.0)
- SteelSeries Sonar's ClearCast AI "does require the software to be running in the background" — [SteelSeries blog](https://steelseries.com/en-si/blog/how-to-eliminate-noise-from-microphone-communication-869)
- APOs take effect after the audio service restarts (installed persistently per endpoint) — [Equalizer APO Documentation](https://sourceforge.net/p/equalizerapo/wiki/Documentation/)
- macOS: TCC permission is keyed to signing identity and persists per bundle id (`tccutil reset SystemAudioCaptureRequests <bundle-id>` clears it) — [DGR Labs](https://dgrlabs.co/blog/2026-04-25-capturing-system-audio-on-macos-in-2026.html); Background Music restores the previous default device on quit (virtual-device approach must manage default-device state) — [BackgroundMusic](https://github.com/kyleneideck/BackgroundMusic)

### Inferences
- Windows: a Session-0 service can capture, but rendering to the interactive user's device and GPU/NPU access from Session 0 are unverified; a per-user auto-start (Task Scheduler "at logon" / Run key) process is the lower-risk choice.
- macOS: a LaunchAgent (per-user, runs at login) hosting the tap IOProc is the natural fit; TCC approval must be obtained interactively once.

### Gaps
- No source on Windows Session-0 render restrictions or on macOS LaunchAgent + TCC system-audio behaviour was retrieved.
